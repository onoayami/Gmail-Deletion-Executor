# Gmail 指定ラベル/送信元 定期自動削除スクリプト

Google スプレッドシート上で設定した条件（特定のラベルや送信元＋経過日数）に基づいて、Gmailの不要なメールを自動でゴミ箱へ移動する Google Apps Script (GAS) です。ゴミ箱に移動させるだけなので、間違っても即情報が消えることはないので安心して使っていただけます。使用するスプレッドシート用GASコードもスプレッドシートの拡張機能に紐づけるだけなので簡単です。

## 機能
- **ラベル指定削除**: 指定した特定のラベルがついた古いメールをゴミ箱に移動します。
- **送信元（From）指定削除**: 特定の送信元からの古いメールをゴミ箱に移動します。
- **経過日数の指定**: 「○日前のメールをゴミ箱に移動」といった期間指定が可能です（全体設定、または条件ごとの個別設定が可能）。
- **スター付きメールの保護**: ラベル/送信元で削除対象になっても、スター（★）が付いているメールは、削除対象外となります。
- **手動実行・停止メニュー**: スプレッドシートの独自メニューから、ボタン一つで手動実行や、全設定の一括停止（緊急全停止）が可能です。手動実行時のログも自動でシートに記録されます。

## 🚀 使い方（セットアップ手順）

### 1. スプレッドシートの準備
新規のGoogleスプレッドシートを作成し、以下の名前でシート（タブ）を作成・設定してください。
（※未作成の状態でスクリプトを実行すると、一部のシートは自動生成されます）

- **削除ラベル設定**
  - A列: ラベル名
  - B列: チェックボックス (チェックを入れると実行対象)
  - C列: 個別指定日数 (空欄の場合は、全体設定を適用)
  - D列: 備考（手動実行結果などが書き込まれます）
- **削除送信元設定**
  - A列: 送信元アドレス（例: example@test.com）
  - B列: チェックボックス (チェックを入れると実行対象)
  - C列: 個別指定日数 (空欄の場合は、全体設定を適用)
  - D列: 備考
- **その他削除設定**
  - B2セルに「何日前のものを削除するか」の全体設定値を半角で入力します。
- **手動発火ログ** 
  - 手動実行時に自動生成・記録されます。
  - 拡張機能のトリガー設定で毎日関数を自動するようにした場合、そのログは残りません。

### 2. GASへのスプレッドシート用GASコードの反映
1. 作成したスプレッドシートのメニューから `拡張機能` > `Apps Script` を開きます。
2. 初期からある `コード.gs` の内容を消し、このリポジトリの [スプレッドシート用GASコード.js](./スプレッドシート用GASコード.js) の内容をコピペして保存します。
※ 本リポジトリには `appsscript.json` は含めていません。タイムゾーン等の設定は各々のローカル設定に合わせてご利用ください。
※ `clasp` を利用して開発される場合も、ローカル環境に合わせて自動生成される `appsscript.json` をそのままご利用いただいて問題ありません。

### 3. 初期設定と権限の承認
1. スプレッドシートをリロードします。数秒経つと、上部メニューの「ヘルプ」の横に「【設定手動アップデート 🗑️💨】」が表示されます。
2. メニューから「設定を手動で反映させる」を実行します。
3. 初回実行時はGoogleから「承認が必要」というポップアップが出ます。画面の指示に従ってアクセス権限を許可（`詳細` -> `（安全ではないページ）に移動` など）してください。
4. 設定した条件に基づき、不要なメールが実際にゴミ箱へ移動することを確認してください（結果は「手動発火ログ」に記録されます）。

### 4. 定期実行（トリガー）の設定
自動で定期的に削除（クリーンアップ）されるようにするには、GASエディタの画面左側にある時計アイコン（トリガー）から以下のように新しくトリガーを追加します。
- **実行する関数**: `executeAllDeletions`
- **デプロイ時に実行**: `Head`
- **イベントのソース**: `時間主導型`
- **時間ベースのトリガーのタイプ**: `日ベースのタイマー`（お好みで変更可）
- **時刻を選択**: （お好みの時間帯を選択）

## ⚠️ 注意点
- ゴミ箱に移動したメールは、Gmailの仕様により **30日後** に自動的に完全削除されます。
- 一度に取得・処理するメール数は、GASの実行時間上限（6分）のタイムアウト等を防ぐため、各条件ごとに 最大100件 までに制限しています。100件を超える場合は次回の実行時に順次削除されます。
- 重要なメールが意図せず削除されないよう、導入時は慎重にテスト設定を行ってください。
